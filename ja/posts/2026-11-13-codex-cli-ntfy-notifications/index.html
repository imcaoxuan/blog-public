Send Codex CLI Notifications to iPhone and Apple Watch with ntfy

Send a short completion notice from Codex CLI through a self-hosted ntfy server and keep approval alerts in macOS Terminal.

目次

  • エンドツーエンドテストを行う

私は自ホストの ntfy サーバーを利用して、Codex CLI の完了通知を iPhone と Apple Watch に送信しています。メッセージにはプロジェクトディレクトリ名と短い状態が含まれます。承認のプロンプトを表示すると、macOS Terminal のターミナルベルが鳴ります。

プライベートトピックを準備する#

ntfy サーバーに通常のユーザーを作成し、codex トピックへのアクセス権を追加します。Docker で展開している場合は、ntfy コンテナ内で次のコマンドを実行してください。

ntfy user add codex
ntfy access codex codex rw
ntfy token add --label="Codex CLI" codex

この例では、認証が有効で、匿名ユーザーにはそのトピックへのアクセス権がないことを前提としています。ntfy iOS アプリに自ホストのサーバーを追加し、ユーザー名とパスワードを使用して codex を購読します。生成された tk_… トークンは、CLI からメッセージを公開するために保管してください。この例では、同じアカウントでメッセージを公開して購読できます。ntfy のアクセス制御ドキュメントを参照してください。

iOS のバックグラウンド配信を有効にする#

次のキーを現在使用中のサーバー設定に統合し、ntfy を再起動します。アプリ内のスキーム、ホスト名、ポートは base-url の設定と一致させる必要があります。

base-url: "https://ntfy.example.com"
upstream-base-url: "https://ntfy.sh"

自ホストの通知では、上流へのリクエストにメッセージ ID と完全なトピック URL の SHA-256 ハッシュ値が含まれます。上流サービスでは、サーバーの送信元 IP とリクエストのタイミングも観測できます。Firebase と APNs がWake 信号を中継します。その後、iPhone は自ホストのサーバーから通知本文を取得するため、外出先でもサーバーにアクセスできる必要があります。たとえば VPN を使用してください。ntfy の iOS 配信ドキュメントを参照してください。

通知スクリプトをインストールする#

Codex を実行するユーザーアカウントの ~/.codex/codex-notify.sh として保存します。サンプルのトピック URL を置き換えてください。jq をインストールすると、通知にプロジェクト名を含められます。インストールしない場合は、完了状態だけが通知に含まれます。

#!/bin/sh

# Set topic_url here, or pass the URL before the optional Codex event JSON.
# Set NTFY_TOKEN in the environment if the topic requires authentication.
topic_url='https://ntfy.example.com/codex'

case ${1:-} in
    http://*|https://*)
        topic_url=$1
        shift
        ;;
esac

if [ -z "$topic_url" ]; then
    printf 'Set topic_url in %s or pass the ntfy topic URL as the first argument.\n' "$0" >&2
    exit 2
fi

message='Codex finished its turn.'
if [ "$#" -gt 0 ] && command -v jq >/dev/null 2>&1; then
    project=$(printf '%s' "$1" | jq -er '
        .cwd | strings | split("/") | map(select(length > 0)) | last | strings | .[:120]
    ' 2>/dev/null) && [ -n "$project" ] && message=$(printf 'Project: %s\n%s' "$project" "$message")
fi

set -- --fail --silent --show-error --max-time 10 \
    --output /dev/null \
    --header 'Title: Codex' \
    --data-binary "$message" \
    --url "$topic_url"

if [ -n "${NTFY_TOKEN:-}" ]; then
    printf 'Authorization: Bearer %s\n' "$NTFY_TOKEN" |
        curl --disable "$@" --header @-
else
    exec curl --disable "$@"
fi

~/.codex/config.toml では、notify を最初の TOML テーブルヘッダーの前に配置します。すでに [tui] テーブルがある場合は、次の 3 つのキーをそのテーブルに追加します。サンプルの絶対パスを自分のパスに置き換えてください。

notify = ["/bin/sh", "/Users/your-user/.codex/codex-notify.sh"]

[tui]
notifications = ["approval-requested"]
notification_method = "bel"
notification_condition = "unfocused"

現在使用中のプロファイルについては、Terminal → 設定 → プロファイル → 詳細 で、音响ベルまたはバックグラウンドでの Dock アイコンの跳ね返りを有効にします。完了フックは、各ターンの終了後に実行されます。ターミナルにフォーカスがない状態で承認リクエストが表示されると、ターミナルベルでお知らせします。この設定では即時通知を使用します。Codex の通知設定と Terminal のプロファイル設定を参照してください。

エンドツーエンドテストを行う#

Codex を起動する zsh セッションで、公開トークンを入力し、完了したターンをシミュレートします。トークンの入力はエコーされず、コマンド履歴にも記録されません。

read -rs 'NTFY_TOKEN?Paste the ntfy token: '
printf '\n'
export NTFY_TOKEN

/bin/sh ~/.codex/codex-notify.sh \
  '{"type":"agent-turn-complete","cwd":"/tmp/example-project"}'

テスト前に iPhone をロックし、完了通知が届いたか確認します。同じシェルから Codex を起動し、短いターンを実行してフックをテストします。Apple Watch については、iPhone の division → 通知 設定で ntfy を有効にし、ロック解除した手表を装着してから、別のメッセージを送信する前に手机をロックしてください。Apple Watch の通知ルーティングを参照してください。

アプリを開いた後にしかメッセージが表示されない場合は、まず公開の ntfy.sh サーバー上の一時的なトピックでダミー 메시ージをテストします。プッシュが成功する場合は、自ホストサーバーの現在有効な上流設定と送信接続を確認してから、プライベート購読を一度削除して再度追加し、プッシュ登録を更新します。iOS に 新しいメッセージ としか表示されない場合は、本文を取得するために自ホストサーバーにアクセスできるか確認してください。ntfy の iOS トラブルシューティングを参照してください。
