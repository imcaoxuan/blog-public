Send Codex CLI Notifications to iPhone and Apple Watch with ntfy

Send a short completion notice from Codex CLI through a self-hosted ntfy server and keep approval alerts in macOS Terminal.

I use a self-hosted ntfy server to send Codex CLI completion notices to my iPhone and Apple Watch. The message contains the project directory name and a short status. Approval prompts use the macOS Terminal bell.

Prepare a private topic#

On the ntfy server, create a regular user and grant it access to the codex topic. Run these commands inside the ntfy container if you deploy with Docker.

ntfy user add codex
ntfy access codex codex rw
ntfy token add --label="Codex CLI" codex

This example assumes authentication is enabled and anonymous access to the topic is denied. In the ntfy iOS app, add your self-hosted server and subscribe to codex with the username and password. Keep the generated tk_… token for publishing from the CLI. The same account can publish and subscribe in this example. See the ntfy access-control documentation.

Enable iOS background delivery#

Merge these keys into the active server configuration and restart ntfy. Use the same scheme, hostname, and port in the app and in base-url.

base-url: "https://ntfy.example.com"
upstream-base-url: "https://ntfy.sh"

For self-hosted notifications, the upstream request carries a message ID and the SHA-256 hash of the complete topic URL. The upstream service can also observe the server’s egress IP and request timing. Firebase and APNs deliver the wake-up signal. The iPhone then retrieves the notification text from the self-hosted server, so it needs access to that server while away from home, for example through a VPN. See the ntfy iOS delivery documentation.

Install the notification script#

Save this as ~/.codex/codex-notify.sh under the account that runs Codex. Replace the example topic URL. Install jq to include the project name. Without it, the notification contains only the completion status.

#!/bin/sh

# Set topic_url here, or pass the URL before the optional Codex event JSON.
# Set NTFY_TOKEN in the environment if the topic requires authentication.
topic_url='https://ntfy.example.com/codex'

case ${1:-} in
    http://*|https://*)
        topic_url=$1
        shift
        ;;
esac

if [ -z "$topic_url" ]; then
    printf 'Set topic_url in %s or pass the ntfy topic URL as the first argument.\n' "$0" >&2
    exit 2
fi

message='Codex finished its turn.'
if [ "$#" -gt 0 ] && command -v jq >/dev/null 2>&1; then
    project=$(printf '%s' "$1" | jq -er '
        .cwd | strings | split("/") | map(select(length > 0)) | last | strings | .[:120]
    ' 2>/dev/null) && [ -n "$project" ] && message=$(printf 'Project: %s\n%s' "$project" "$message")
fi

set -- --fail --silent --show-error --max-time 10 \
    --output /dev/null \
    --header 'Title: Codex' \
    --data-binary "$message" \
    --url "$topic_url"

if [ -n "${NTFY_TOKEN:-}" ]; then
    printf 'Authorization: Bearer %s\n' "$NTFY_TOKEN" |
        curl --disable "$@" --header @-
else
    exec curl --disable "$@"
fi

In ~/.codex/config.toml, put notify above the first TOML table header. If you already have a [tui] table, add the three keys to it. Replace the example absolute path with your own.

notify = ["/bin/sh", "/Users/your-user/.codex/codex-notify.sh"]

[tui]
notifications = ["approval-requested"]
notification_method = "bel"
notification_condition = "unfocused"

Enable the audible bell or background Dock bounce under Terminal → Settings → Profiles → Advanced for your active profile. The completion hook runs after each finished turn. The terminal bell alerts you when an approval appears while the terminal is unfocused. This setup uses immediate notifications. See the Codex notification settings and Terminal profile settings.

Test end to end#

In the zsh session that will launch Codex, enter the publishing token and simulate a completed turn. The token is read without echo and stays out of the command history.

read -rs 'NTFY_TOKEN?Paste the ntfy token: '
printf '\n'
export NTFY_TOKEN

/bin/sh ~/.codex/codex-notify.sh \
  '{"type":"agent-turn-complete","cwd":"/tmp/example-project"}'

Lock the iPhone before testing and check for the completion notice. Launch Codex from the same shell and run a short turn to test the hook. For Apple Watch, enable ntfy in the iPhone’s Watch → Notifications settings, wear the unlocked watch, and lock the phone before sending another message. See Apple Watch notification routing.

If messages appear only when you open the app, test a temporary topic on the public ntfy.sh server with a dummy message. If that pushes successfully, check the self-hosted server’s active upstream configuration and outbound connectivity, then remove and re-add the private subscription to refresh its push registration. If iOS shows only New message, check whether it can reach the self-hosted server to fetch the body. See the ntfy iOS troubleshooting notes.
