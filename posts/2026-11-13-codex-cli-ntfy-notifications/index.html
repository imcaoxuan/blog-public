Send Codex CLI Notifications to iPhone and Apple Watch with ntfy

Send a short completion notice from Codex CLI through a self-hosted ntfy server and keep approval alerts in macOS Terminal.

我使用自托管的 ntfy 服务器，将 Codex CLI 的完成通知发送到我的 iPhone 和 Apple Watch。消息包含项目目录名称和简短状态。审批提示会触发 macOS Terminal 的终端响铃。

准备私有主题#

在 ntfy 服务器上创建一个普通用户，并授予其对 codex 主题的访问权限。如果使用 Docker 部署，请在 ntfy 容器内运行以下命令。

ntfy user add codex
ntfy access codex codex rw
ntfy token add --label="Codex CLI" codex

此示例假定已启用身份验证，且匿名用户无权访问该主题。在 ntfy iOS 应用中添加你的自托管服务器，并使用用户名和密码订阅 codex。保留生成的 tk_… 令牌，以便从 CLI 发布消息。在此示例中，同一个账户既可以发布消息，也可以订阅消息。请参阅 ntfy 访问控制文档。

启用 iOS 后台传递#

将以下键合并到当前使用的服务器配置中，然后重启 ntfy。应用中的方案、主机名和端口应与 base-url 中的设置保持一致。

base-url: "https://ntfy.example.com"
upstream-base-url: "https://ntfy.sh"

对于自托管通知，上游请求会携带消息 ID 和完整主题 URL 的 SHA-256 哈希值。上游服务还可以观察到服务器的出口 IP 和请求时序。Firebase 和 APNs 会传递唤醒信号。随后，iPhone 会从自托管服务器获取通知文本，因此离开家时需要能够访问该服务器，例如通过 VPN。请参阅 ntfy iOS 传递文档。

安装通知脚本#

将其保存为运行 Codex 的用户账户下的 ~/.codex/codex-notify.sh。替换示例主题 URL。安装 jq 后即可在通知中包含项目名称；如果不安装，通知将只包含完成状态。

#!/bin/sh

# Set topic_url here, or pass the URL before the optional Codex event JSON.
# Set NTFY_TOKEN in the environment if the topic requires authentication.
topic_url='https://ntfy.example.com/codex'

case ${1:-} in
    http://*|https://*)
        topic_url=$1
        shift
        ;;
esac

if [ -z "$topic_url" ]; then
    printf 'Set topic_url in %s or pass the ntfy topic URL as the first argument.\n' "$0" >&2
    exit 2
fi

message='Codex finished its turn.'
if [ "$#" -gt 0 ] && command -v jq >/dev/null 2>&1; then
    project=$(printf '%s' "$1" | jq -er '
        .cwd | strings | split("/") | map(select(length > 0)) | last | strings | .[:120]
    ' 2>/dev/null) && [ -n "$project" ] && message=$(printf 'Project: %s\n%s' "$project" "$message")
fi

set -- --fail --silent --show-error --max-time 10 \
    --output /dev/null \
    --header 'Title: Codex' \
    --data-binary "$message" \
    --url "$topic_url"

if [ -n "${NTFY_TOKEN:-}" ]; then
    printf 'Authorization: Bearer %s\n' "$NTFY_TOKEN" |
        curl --disable "$@" --header @-
else
    exec curl --disable "$@"
fi

在 ~/.codex/config.toml 中，将 notify 放在第一个 TOML 表头之前。如果已经有 [tui] 表，请将以下三个键添加到该表中。将示例绝对路径替换为你自己的路径。

notify = ["/bin/sh", "/Users/your-user/.codex/codex-notify.sh"]

[tui]
notifications = ["approval-requested"]
notification_method = "bel"
notification_condition = "unfocused"

对于当前使用的描述文件，在 Terminal → 设置 → 描述文件 → 高级 中启用声音响铃或后台 Dock 弹跳。完成钩子会在每轮操作结束后运行。当终端未聚焦时出现审批请求，终端响铃会提醒你。此设置使用即时通知。请参阅 Codex 通知设置和 Terminal 描述文件设置。

进行端到端测试#

在将要启动 Codex 的 zsh 会话中，输入发布令牌并模拟一轮已完成的操作。令牌读取时不会回显，也不会进入命令历史记录。

read -rs 'NTFY_TOKEN?Paste the ntfy token: '
printf '\n'
export NTFY_TOKEN

/bin/sh ~/.codex/codex-notify.sh \
  '{"type":"agent-turn-complete","cwd":"/tmp/example-project"}'

测试前锁定 iPhone，然后检查是否收到完成通知。从同一个 shell 启动 Codex，并运行一个简短轮次来测试钩子。对于 Apple Watch，请在 iPhone 的 手表 → 通知 设置中启用 ntfy，佩戴已解锁的手表，并在发送另一条消息前锁定手机。请参阅 Apple Watch 通知路由。

如果只有在打开应用后才会看到消息，请先在公共 ntfy.sh 服务器上用一个虚拟消息测试临时主题。如果推送成功，请检查自托管服务器当前生效的上游配置和出站连接，然后移除并重新添加私有订阅，以刷新其推送注册。如果 iOS 只显示 新消息，请检查它是否能够访问自托管服务器以获取正文。请参阅 ntfy iOS 故障排查说明。
